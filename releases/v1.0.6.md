# AlwaysStrongFork v1.0.6

Stable release fixing boot-safe recovery and Zygisk payload handling.

Previously, after boot-safe disabled the module, enabling it again could leave
the scripts stopped while the bundled Zygisk libraries remained available to
the provider. This release quarantines those libraries as well.

## What changed

- Move the bundled `zygisk/` payload to `.boot-safe-zygisk/` when boot-safe trips.
- Keep it quarantined after a manager enable toggle; reassert `disable` before
  startup deadlines and service locks, even if the native helper is unavailable.
- Preserve a previous safety latch during updates and quarantine the new staged
  libraries before the root manager activates the update.
- Provide explicit recovery under the boot-guard lock. Recovery requires Android
  boot completion, restores the payload and clears the retry counter, and keeps
  the module disabled until the user enables it and reboots.
- Add quarantine status and the boot-safety log to collected diagnostics.
- Add regression fixtures for boot-safe, re-enabling, updates, missing helpers,
  repeat quarantine, recovery and Lite. Synchronize versionCode 116 and updater
  metadata across the existing release variants.

## Updating and recovery

Install the matching main ZIP through the root manager and reboot. Use the plain
ZIP for the default PlayIntegrityFork build, `-inject` for Inject, or `-nopif` for
Lite. The Isolation ZIP remains a separate optional companion.

An existing boot-safe block deliberately survives the update. After fixing the
cause and booting Android with the module disabled, run in a root shell:

```sh
sh /data/adb/modules/tricky_store/boot_safety.sh recover
```

Then enable the module in the manager and reboot to retry. Action and WebUI
settings reset do not clear this safety block. Lite does not quarantine a
separately installed PIF, and this module does not disable the optional Isolation
companion or any other module.

The change prevents future loads from the module's Zygisk paths; it cannot unload
libraries already opened or mapped by a provider during the current boot. Host
and CI regression checks do not replace a physical Android boot test. The PIF
and TEESimulator-RS v6.0.1-307 upstream payload pins are unchanged; this release
does not guarantee any particular Play Integrity verdict.
