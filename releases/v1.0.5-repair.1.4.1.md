## Optional companion

- Select exact package names in the companion's WebUI. The initial selection is Duck Detector, matching the supplied report.
- For selected apps, optionally replace read-only private module font mappings with anonymous read-only copies at the same addresses. Font bytes and original files are preserved. The option defaults to on and can be disabled in WebUI.
- Request Zygisk's per-process module unmount operation, then unload the companion's own library. No persistent function hooks are installed.
- Exclude Google Play components, Soter, system UIDs, root-granted UIDs, and isolated UIDs.
- Require a compatible **Zygisk API v5 provider**, Android 10+, ARM64/ARMv7. Magisk requires version 27000+; KernelSU/APatch depend on their Zygisk provider and are not device-verified.

After installing the companion, reboot and fully restart the selected app. If rendering/stability changes, disable private font copies or disable the companion and reboot. Private copies consume additional memory. There is no guarantee of a clean detector verdict.

## What remains unresolved

The supplied report's Soter failure occurs during ASK/AuthKey preparation (`finalErr=4`). Hardware/vendor repair is not established. A read-only environment diagnostic is now included in collected logs; vendor keys and services are not modified. PackageManager visibility of installed root/modding apps and Xposed module metadata is also not hidden by mount isolation.

The supplied report predates 1.4.0/1.4.1 and cannot verify the new behavior. See [report analysis](https://github.com/zaigraevstepan7-afk/Alwaysstrongfork/blob/main/docs/DETECTOR_REPORT.md).
