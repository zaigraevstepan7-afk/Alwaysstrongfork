# AlwaysStrongFork · Repair 1.4.0

**Fork author: [@SUKISU_ULTR4](https://t.me/SUKISU_ULTR4)**

Support: [@alwaysstrongfork](https://t.me/alwaysstrongfork)

This release improves startup property consistency and adds optional app-target DenyList synchronization. versionCode: **112**.

## Changes

- **Close a TEE startup race.** Boot/debug property settings previously ran in a background block that could finish after TEE started. A shared, bounded policy now runs synchronously before starting an engine and before each owned daemon restart.
- **Verify property writes.** Existing OEM verified-boot, lock, verity, warranty, debug, and build type/tag aliases follow one policy. Writes are read back. Failure or timeout skips that new engine launch and is recorded in `boot-props.log`.
- **Optional selected-app hiding list.** WebUI → Advanced → Targeting → **Sync targets to DenyList**, then run Action. Adds selected app main processes and currently running package-prefixed subprocesses to Magisk DenyList. Target-list rebuilds repeat the sync.
- **Preserve user control.** Target synchronization defaults to off, requires a compatible external hider, and is skipped with DenyList enforcement on. Existing entries and the enforcement toggle are preserved. Turning synchronization off does not remove previous entries.
- **Better diagnostics.** Collected reports include property-policy and DenyList logs.
- **Regression coverage.** Added 10 isolated property-policy/startup/DenyList tests, for 50 Python + 6 Rust tests in total. CI rebuilds and verifies all three installation ZIPs.

Install one variant through your root manager over the previous Repair build, then reboot. Do not delete `/data/adb/tricky_store`. Android 10+, ARM64/ARMv7, and working root are required; default/Inject also require Zygisk.

If automatic targeting is enabled, the optional DenyList sync can include every user-installed app. Curate the target list first if you need a smaller scope. KernelSU/APatch hiding settings, unrelated custom process names, and isolated processes are not managed by this option.

## Scope and verification limits

TEESimulator-RS remains pinned to **v6.0.1-307**; its native libraries and DEX were not rewritten. This release changes the integration and startup policy. It does not create hardware trust, validate an AVB chain, physically lock the bootloader, or guarantee invisibility to detectors. Property updates do not touch the product identity, encryption state, boot partitions, or persistent property storage.

Host/CI tests do not establish behavior on a physical Android device. After installing, check boot stability and app behavior, run a new independent Play Integrity check, and import its fresh JSON. If problems occur, disable the module and reboot. Disabling and rebooting restores the ROM's session property values; DenyList entries can be removed manually in Magisk.
